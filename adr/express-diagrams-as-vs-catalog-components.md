# Express diagrams as vs catalog components

Date: 2026-08-24

## Context

An analysis of the twenty best-formatted Wix Stash proposals (short,
low-text, illustration-heavy) showed the strongest documents lean on two
visual moves vs HTMDX reports cannot express natively: a linear flow strip
(labeled stages with arrows, read in one glance) and an annotated figure (a
captioned screenshot with numbered callouts). The runtime already renders
mermaid, and authors can inline raw SVG, so the question was where diagram
expressiveness should live: mermaid, hand-authored SVG, upstream `@wix/htmdx`
components, or the vs external catalog in
`skills/vs-htmdx/assets/definitions.mjs`.

## Decision

Recurring diagram shapes in vs artifacts are expressed as vs catalog
components with declarative markdown bodies — starting with `Flow` (linear
strip) and `Figure` (captioned, optionally annotated image) — following the
component contract established by the wix-private/htmdx#5 port: self-wrapped
`section[data-htmdx-component]`, body parsed by the component, palette-scoped
styling, degradation to body text without React, browser copy regenerated by
`assets/sync-artifact-catalog.mjs`.

Each new diagram component must first survive a kill criterion: re-express a
real reference document with and without it; it ships only when the
with-version is visibly better.

## Consequences

- Agents author diagrams as reviewable declarative rows instead of redrawing
  SVG, and every artifact gets the same on-palette rendering.
- The catalog, not the upstream runtime, carries the vs look — no upstream
  release loop, but also no reuse outside vs artifacts.
- Mermaid remains the path for branching graphs, cycles, and swimlanes;
  catalog components stay deliberately narrow (a `Flow` is linear, 3–6
  stages) rather than growing into a diagram engine.
- Saved artifacts snapshot the inline catalog copy, so later catalog changes
  cannot break already-published documents.

## Alternatives considered

- **Mermaid only** — rejected: generated flowcharts read generically, ignore
  the vs palette, and the winners' hand-built strips were consistently
  clearer for linear sequences. Mermaid is kept for genuinely graph-shaped
  content.
- **Recommend raw inline SVG** — rejected: already possible today and the
  gap persisted; every author redraws inconsistently and the source is
  unreviewable.
- **Contribute components upstream to `@wix/htmdx`** — rejected: slower
  iteration loop and the vs look is vs-specific; the 4.15+ external-catalog
  seam exists precisely for this.
